# Трекер квартир newbor.by → Telegram

Периодически открывает страницу подбора квартир с сохранённым фильтром, сравнивает
выдачу с прошлой проверкой и присылает в Telegram сообщение, если появилась новая
квартира.

## Что отслеживаем

Комплекс «Новая Боровая», раздел «Подбор квартиры» (инфоблок `IBLOCK_ID=29`).
Текущий фильтр (`DEFAULT_FILTER_URL` в `check.py`):

| Параметр в ссылке | Свойство | Значение |
|---|---|---|
| `arrFlatFilter_139_MIN=70` | Площадь (`R_SQUARE_C`) | **от 70 м²**, без верхней границы |
| `arrFlatFilter_144_4252452532=Y` + `booked=hide` | Статус (`R_STATUS`) | **только «Свободна»** |
| — | Дом (`R_HOUSE`) | любой |
| — | Цена (`R_PRICE_C`), цена за м² (`PRICE_BYN_PER_METR`) | любая |
| — | Этаж (`R_FLOOR`) | любой |

Верхние границы намеренно не передаются: если бы стоял `_139_MAX=102` (текущий
максимум ползунка), квартира большей площади в выдачу бы не попала.

Другие ID свойств, если захочется сузить фильтр вручную:
`312` — количество комнат, `141` — стоимость BYN, `830` — цена за м² BYN,
`682` — срок сдачи, `146` — дом, `187` — этаж, `176` — особенности,
`408` — тип отделки, `842` — планировка, `835` — стороны света.

Технически: результаты рендерятся на сервере внутри `<div id="getHtml">`,
постранично через `PAGEN_1` (24 карточки на страницу). Скрипт обходит все
страницы, поэтому фильтр можно менять без правок кода.

## Команды бота

Рассылка — на всех подписчиков, а не на один зашитый чат. Подписка управляется
командами в личке бота ([@nb_flat_watcher_bot](https://t.me/nb_flat_watcher_bot)):

| Команда | Что делает |
|---|---|
| `/start` | подписаться (новому подписчику сразу показывается текущая выдача) |
| `/stop` | отписаться |
| `/list` | что подходит под фильтр прямо сейчас |

Любое другое сообщение — короткая справка о боте.

Как это устроено: постоянно работающего процесса нет, поэтому каждый запуск
скрипт забирает накопившиеся сообщения через `getUpdates`, отвечает на них и
сохраняет `tg_offset` и список подписчиков в `state.json`. Отсюда следствие —
**ответ на команду приходит не мгновенно, а в течение ближайшей проверки**
(до 5 минут, иногда дольше из-за задержек GitHub). Об этом бот сам
предупреждает в ответе на `/start` (`DELAY_NOTE` в `check.py`), чтобы никто
не решил, что он сломался.

Меню команд регистрируется через `setMyCommands` и обновляется автоматически,
как только список `BOT_COMMANDS` в коде меняется.

Кто заблокировал бота или удалил чат, отписывается автоматически: Telegram
отдаёт 403/400, и такой chat_id вычищается из списка.

Ссылку на бота можно давать кому угодно — подписаться может любой, кто его
найдёт. Если нужно ограничить круг, проще всего сменить бота на приватного
или добавить проверку `chat_id` по белому списку в `handle_commands`.

Посмотреть подписчиков локально: `python3 check.py --subscribers`.

## Что приходит в Telegram

На каждую новую квартиру — отдельное сообщение: **фото планировки** + подпись с
домом и номером квартиры, комнатами, площадью, этажом, подъездом, ценой в $ и
BYN, ценой за м², отделкой, сроком сдачи, кварталом, особенностями и ссылкой на
карточку. Если новых сразу больше 10, первые 10 идут с планировками, остальные —
одним списком.

## Установка

```bash
cd ~/flat-tracker
cp .env.example .env
```

1. Создай бота: напиши [@BotFather](https://t.me/BotFather) → `/newbot` → получишь токен.
2. Напиши своему боту любое сообщение (иначе он не сможет тебе писать).
3. Узнай chat id: открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьми
   `result[0].message.chat.id`.
4. Впиши оба значения в `.env`.
5. Проверь связь и запомни текущую выдачу, чтобы не получить сразу пачку сообщений:

```bash
python3 check.py --test-telegram
python3 check.py --init
```

6. Включи фоновую проверку каждые 15 минут (только если гоняешь локально,
   а не в GitHub Actions):

```bash
./install.sh
```

## Команды

```bash
python3 check.py              # одна проверка + уведомления
python3 check.py --dry-run    # то же, но сообщения печатаются в консоль
python3 check.py --list       # показать всё, что сейчас в выдаче
python3 check.py --init       # запомнить выдачу молча (сброс «новизны»)
python3 check.py --test-telegram
python3 check.py --subscribers  # кто подписан
```

Управление фоновой задачей:

```bash
launchctl kickstart gui/$(id -u)/by.newbor.flat-tracker   # запустить прямо сейчас
launchctl bootout   gui/$(id -u)/by.newbor.flat-tracker   # выключить
tail -f tracker.log
```

Интервал меняется в `by.newbor.flat-tracker.plist` (`StartInterval`, секунды),
после правки — `./install.sh` ещё раз.

## Настройки

- `FILTER_URL` в `.env` — свой фильтр. Собери его на сайте, примени и скопируй
  ссылку из адресной строки (верхние границы диапазонов из неё лучше убрать).
- `NOTIFY_REMOVED=1` — сообщать ещё и о квартирах, пропавших из выдачи
  (забронировали или продали).

## Где это крутится

Основной вариант — **GitHub Actions**, `.github/workflows/check.yml`: проверка
каждые 5 минут независимо от домашнего компьютера. Что нужно один раз:

1. Settings → Secrets and variables → Actions → добавить `TELEGRAM_BOT_TOKEN`
   и `TELEGRAM_CHAT_ID`.
2. Всё. Расписание включается само; кнопка «Run workflow» на вкладке Actions
   запускает проверку вручную.

Состояние (`state.json`) коммитится обратно в репозиторий (но только
когда меняется что-то содержательное — список квартир или подписчиков,
а не отметка времени последней проверки) — поэтому после
перезапусков и падений трекер помнит, о чём уже сообщал. Раз в неделю
воркфлоу делает пустой коммит-пульс: GitHub отключает расписание в
репозиториях, где 60 дней не было активности.

Локальный запуск через launchd (`install.sh`) остаётся как запасной вариант —
но держать оба сразу не надо, будут дубли уведомлений.

## Нюансы

- Реальный интервал у GitHub плавает: при нагрузке запуск может опоздать
  на 5–20 минут. Это нормально.
- launchd не будит Mac: пока ноутбук спит, локальных проверок нет.
- Состояние хранится в `state.json`. Удалить его = следующая проверка сочтёт
  все текущие квартиры новыми.
- Если сайт поменяет вёрстку, скрипт не «проглотит» это молча: он отличает
  «квартир не найдено» от «не смог распарсить» и после 3 неудач подряд напишет
  в Telegram.
- 5 минут — минимальный интервал, который принимает cron GitHub Actions
  (≈290 запросов к сайту в сутки). Меньше — только своим сервером с вебхуком.
