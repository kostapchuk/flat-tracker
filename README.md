# Трекер квартир newbor.by → Telegram

Следит за подбором квартир в «Новой Боровой» и присылает в Telegram новые
квартиры с планировкой, как только они появляются в продаже.

## Из чего состоит

Две независимые части — общаются через один HTTP-запрос:

```
GitHub Actions (по расписанию)          Deno Deploy (всегда онлайн)
┌────────────────────────────┐          ┌──────────────────────────┐
│ check.py                   │          │ bot/main.ts              │
│  • обходит сайт            │  POST    │  • вебхук Telegram       │
│  • сравнивает с state.json │ /broad-  │  • /start /stop /list    │
│  • нашёл новое ───────────────cast───▶│  • подписчики в Deno KV  │
│                            │  POST    │  • помнит message_id     │
│  • квартира ушла ─────────────retire─▶│  • правит старые сообщения│
│  • коммитит state.json     │          │                          │
└────────────────────────────┘          └──────────────────────────┘
             │                                       ▲
             └── state.json в репозитории ───────────┘
                   (бот читает его для /list)
```

Почему так: обход сайта — работа редкая и тяжёлая, ей место в кроне. А бот
должен отвечать мгновенно, для этого нужен постоянно доступный адрес под
вебхук. Раньше команды разбирались внутри крона, и ответа приходилось ждать
несколько минут.

Тексты сообщений верстает **только** `check.py` и кладёт готовыми в
`state.json` (поле `text` у каждой квартиры). Бот их просто отправляет —
поэтому вёрстка карточки живёт в одном месте, а не в двух.

## Что отслеживаем

Раздел «Подбор квартиры» (инфоблок `IBLOCK_ID=29`). Текущий фильтр
(`DEFAULT_FILTER_URL` в `check.py`):

| Параметр в ссылке | Свойство | Значение |
|---|---|---|
| `arrFlatFilter_139_MIN=70` | Площадь (`R_SQUARE_C`) | **от 70 м²**, без верхней границы |
| `arrFlatFilter_144_4252452532=Y` + `booked=hide` | Статус (`R_STATUS`) | **только «Свободна»** |
| — | Дом (`R_HOUSE`) | любой |
| — | Цена (`R_PRICE_C`), цена за м² (`PRICE_BYN_PER_METR`) | любая |
| — | Этаж (`R_FLOOR`) | любой |

Верхние границы намеренно не передаются: если бы стоял `_139_MAX=102`
(текущий максимум ползунка), квартира большей площади в выдачу бы не попала.

Другие ID свойств, если захочется сузить фильтр: `312` — количество комнат,
`141` — стоимость BYN, `830` — цена за м² BYN, `682` — срок сдачи,
`146` — дом, `187` — этаж, `176` — особенности, `408` — тип отделки,
`842` — планировка, `835` — стороны света.

Результаты рендерятся сервером внутри `<div id="getHtml">`, постранично через
`PAGEN_1` (24 карточки на страницу). Скрипт обходит все страницы, поэтому
фильтр можно менять без правок кода.

## Бот

| Команда | Что делает |
|---|---|
| `/start` | подписаться; новому подписчику сразу показывается текущая выдача |
| `/stop` | отписаться |
| `/list` | что подходит под фильтр прямо сейчас |

Любое другое сообщение — короткая справка. Подписчики хранятся в Deno KV;
`OWNER_CHAT_ID` подписан всегда. Кто заблокировал бота, отписывается сам:
Telegram отдаёт 403, и запись удаляется из KV.

На каждую новую квартиру приходит отдельное сообщение: **фото планировки** +
дом и номер квартиры, комнаты, площадь, этаж, подъезд, цены в $ и BYN, цена
за м², отделка, срок сдачи, квартал, особенности и ссылка на карточку.
Если новых сразу больше 10, первые 10 идут с планировками, остальные списком.

**Когда квартиру бронируют или продают**, бот не шлёт новое уведомление, а
редактирует то самое сообщение, которым её присылал: заголовок зачёркивается
и появляется пометка «Забронирована или продана». Для этого он хранит в KV
`message_id` каждой отправленной карточки. Telegram разрешает редактировать
свои сообщения только 48 часов — если карточка старше, придёт короткое новое
сообщение вместо правки. Команда `/list` всегда показывает только актуальное:
она читает `state.json`, откуда ушедшие квартиры уже удалены.

### Развернуть бота на Deno Deploy

1. https://dash.deno.com → войти через GitHub → **New Project** → выбрать
   репозиторий `flat-tracker`, точка входа `bot/main.ts`.
2. Settings → Environment Variables:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `WEBHOOK_SECRET` | любая случайная строка |
   | `BROADCAST_SECRET` | любая случайная строка (её же — в секреты GitHub) |
   | `OWNER_CHAT_ID` | твой chat_id, подписан всегда |
   | `STATE_URL` | `https://raw.githubusercontent.com/<юзер>/flat-tracker/main/state.json` |

3. Привязать вебхук и меню команд — один раз, из браузера или терминала:

   ```bash
   curl "https://<проект>.deno.dev/setup?key=<BROADCAST_SECRET>"
   ```

   В ответе должно быть `"ok": true` у `webhook` и у `commands`.
4. В GitHub: Settings → Secrets and variables → Actions добавить
   `BOT_URL` = `https://<проект>.deno.dev` и
   `BROADCAST_SECRET` = та же строка, что в Deno Deploy.

Проверка: `https://<проект>.deno.dev/` отвечает числом подписчиков.

## Проверялка

Запускается воркфлоу `.github/workflows/check.yml` по расписанию; секреты
`BOT_URL` и `BROADCAST_SECRET` — из шага 4 выше. Если их не задать,
`check.py` шлёт напрямую в `TELEGRAM_CHAT_ID` — удобно для локальных прогонов.

`state.json` коммитится обратно в репозиторий, но только когда меняется
что-то содержательное: список квартир, а не отметка времени последней
проверки. Раз в неделю воркфлоу делает пустой коммит-пульс — GitHub отключает
расписание в репозиториях, где 60 дней не было активности.

Локальные команды:

```bash
python3 check.py              # одна проверка + рассылка
python3 check.py --dry-run    # то же, но сообщения печатаются в консоль
python3 check.py --list       # показать всё, что сейчас в выдаче
python3 check.py --init       # запомнить выдачу молча (сброс «новизны»)
python3 check.py --test-telegram
```

Есть и запуск через launchd на macOS (`install.sh`, `by.newbor.flat-tracker.plist`)
— как запасной вариант, если GitHub Actions недоступен. Держать оба сразу не
надо: будут дубли уведомлений.

## Настройки

- `FILTER_URL` — свой фильтр. Собери его на сайте, примени и скопируй ссылку
  из адресной строки (верхние границы диапазонов лучше убрать).

## Нюансы

- Реальный интервал у GitHub плавает: запуск может опоздать на 5–20 минут,
  а при нагрузке короткие интервалы иногда пропускаются. На ответы бота это
  больше не влияет — только на скорость обнаружения новой квартиры.
- Время в `state.json` (`last_ok_utc`) — всегда UTC, с суффиксом `Z`.
- Удалить `state.json` = следующая проверка сочтёт все квартиры новыми.
- Если сайт поменяет вёрстку, скрипт не проглотит это молча: он отличает
  «квартир не найдено» от «не смог распарсить» и после 3 неудач подряд
  напишет в Telegram.
